# 心跳回忆 ~传说之树下~ (SFC) 破解笔记

ROM: `Tokimeki Memorial - Densetsu no Ki no Shita de (Japan) (Rev 1).sfc`
CRC32 = `AE9F3602`（与 2022 英化补丁 "Heartthrob Memorial" 要求的目标 ROM 完全一致）。

## ★ 文本编码破解状态（诚实版，经审查修正）

### ✅ 已证明（有定量验证）
**双字节码 = Shift-JIS 整页重映射**（平假名/全角字母部分 100% 成立）：
```
SJIS_hi = (code_hi + 0x92) & 0xFF
SJIS_lo = (code_lo - 0x0B) & 0xFF      ← 各字节独立回绕
```
- 实测锚点：名字输入写RAM あ→F0AB；い→F0AD（蓝框逐格移动核实）
- 「ありがとう」以该变换在 ROM 中精确命中 8 处；「ます」13 处；「おばあさん」等
  完整短语逐字解码正确
- 对照组（原始 SJIS / 错误偏移变体）：400 短语 0 命中 —— 排除巧合

**单字节 DTE 码表（0x40-0x9F）**：定义表在文件 0x18000（2字节/项 BE）。
按五十音位置修正后（v2，含浊音！）：
- `0x4F`=ん，`0x50`=ぁ `0x51`=あ `0x52`=ぃ `0x53`=い …（偶数槽=小写假名）
- `0x5A`=か `0x5B`=が … `0x7F`=ば `0x80`=ぱ `0x81`=ひ `0x84`=ふ `0x87`=へ
  `0x8D`=ま `0x93`=や `0x9C`=ろ `0x9E`=わ `0x9F`=を
- 结构完美（假名按五十音 + 浊音占位），见 `out/table.txt`
- ⚠️ 其中 ~15% 槽位的等价双字节码落在 cp932 未定义区 → 游戏自定义字形，
  身份按五十音位置推定（16 个实测锚点全部吻合）

### ⚠️ 已定位但未破解（这是"文本不成句"的真正原因）
**汉字层**：
- 对话中汉字以 **F1-F8 双字节码族** 和 **A0-EB 单字节码** 出现
- 这两层 = 词典索引/DTE 汉字码，**不是** SJIS 映射——上面的公式对它们无效
- 候选机制：排序词典（0x2196A8 起的有序 16 位表）= 码→字形索引；语义未破
- 因此当前 rom_dump 输出 = "假名骨架可读 + 汉字占位符"，读不成完整句子

**其他未决**：
- 单/双字节令牌的精确边界规则（有 1 字节 DTE 与 2 字节混排，切分歧义）
- 控制码语义（0x0A=换行、0x09=空格已确认，其余待定）
- F1-F8 页中 lo<0x40 的令牌（标点，J2E 表：F003=, F004=. F006=:）
- 部分文本区域疑似另有压缩层（高熵池，如 0x22F40C）

### 验证数据（2026-09 审查）
| 变换 | 400 短语命中率 |
|---|---|
| 原始 SJIS（无重映射） | 0 |
| 错误变体 ×2 | 0 |

结论：**假名层+码表=已证明；汉字层=未破解**。早先"85-90% 可读"的说法作废，
以本节为准。

### 汉字层进展（第二轮，2026-09 深夜）
- **单字节假名表已含浊音**：0x50-0x9F 按五十音完整覆盖（ぁあぃい…かがきぎ…ばぱひびぴ…），
  早先的"暁淫葦栄"错解 = 浊音槽被按 cp932 硬解所致，已按位置修正（out/table.txt）
- **单字节码不止假名**：0xA0-0xFF 区间 = 高频汉字/词组 DTE 码（J2E 口径 "A0-EF"），
  定义 = 0x1CCCA3 指针 + 0x1CCD31 条目（语义未破）
- **词组字典表定位**：0x186E1-0x196E0 区域 = 条目以 `FB46 0A` 结尾的词组表
  （J2E 的 IPS 正是重写此区，33 条记录零星分布；dtek.txt = 他们的英文替换列表）
- **汉字双字节码 = 多页码表，每页一个 SJIS 增量**（审查后确认的最终模型）：
  | 页增量 | 例证 | 可信度 |
  |---|---|---|
  | +6E0B | 假名全体（あ=F0AB 模拟器实测）+ おばあさん 等 | ★★★ 实测+多处命中 |
  | +6706 | 清川 F7BA/F7F2（同场景 5 处一致） | ★★★ 多次一致对齐 |
  | +6DBD | デマ F123/F13A（やっぱり、デマか） | ★★ 两字一致 |
  | +64E7 | 話 FD49（どこからそういう話が） | ★★ 文脉唯一解 |
  不同页增量共存于同一场景 = 页由控制令牌切换；-6E0B 通解假说已被
  清川反例否定（-6E0B 把清川解成"憶臥"）。每页的完整增量需按页破解，
  或从 ROM 页偏移表读取（简单递减表扫描未命中，表结构待查）
- **对齐工具**：tools/align_table.py（v3 opcode 对齐器）——把 ROM 解码骨架与 J2E 场景
  逐句配对，自动提取 码→字 对。当前 52 句匹配/33 对提取（阈值 0.7，可调宽换取覆盖）
- 验证：清川 5 处一致、デマ/つめてぇ/どうしたんだろう 与 TOKSC65 逐句吻合


### 多页码表系统（第三轮发现，解释全部"乱码"现象）
- 同一单字节码在不同段落映射到**不同字符**（实测：同场景内 の→い、に→は 的换页现象）
- **文本流中的控制令牌（⟦2E⟧⟦42⟧⟦23⟧⟦3A⟧⟦40⟧⟦48⟧ 等）会切换当前码表页**
- J2E 归档里的 3 个不同 tbl 文件（tokie2/tokex/toknodte）= 他们整理的不同页
- 码表页数据推测位于 0x18000（页1=假名，已破解）、0x18200+（后续页）、0x1CCCA3/0x1CCD31（A0-EF 汉字词组页）
- **这解释了此前所有"乱码"**：不是解码公式错，而是用页1的表去解了页2/3的文本
- 应对：tools/crack2.py 自举破解器（J2E 全语料已知明文 + opcode 对齐 + 多数投票迭代），
  已提取 120 条映射（out/table_kanji.json + out/text/rom_dump2/），覆盖率待扩大区域/轮次提升
- 替代方案：bsnes 断点抓"换页控制码→码表基址"的切换逻辑，一步定位所有页的表头


### ★ J2E 工作日志完全破译（第三轮核心成果）— 令牌语法权威版
来源：reference/j2e_archive/tokilog_toki.txt（J2E 2003 年逆向笔记）。要点：

**令牌语法（82/A593 解析例程，日志原文确认）**：
| 码域 | 含义 |
|---|---|
| 0x40-0x9F | 单字节假名（表 @0x18000 = "byte→font 查找表"日志原话） |
| 0xA0-0xBF | 双字节（前缀 A0/B0 + 字节）|
| 0xC0-0xCF | C0 + 字节 = 说话人标记（"usually a #$C0 and then a byte saying which person"）|
| 0xD0-0xDF | 单字节特殊（"Dx uses x as the byte"）|
| 0xE0-0xEF | 控制跳转表 |
| 0xF0-0xFF | 双字节假名/汉字族（F0AB=あ 实测）|

**表位置（J2E 偏移 = 无头格式；"with header" = +0x200）**：
- 0x18000 = "look up table for which byte corresponds with the font"（假名表✓已破解）
- 0x1CCAA3 = **A0-E7 指针表**（72 项 LE16，升序）→ 词条区紧随其后 0x1CCB33
  - 指针换算：**文件地址 = 0x1C8000 + (指针 - 0x8000)**
  - 词条 = 动词活用表（F002/F008/F009 = あ/い/う 词干 + 0C/36/14 0A 词尾模式）
- 0x2196A8 = E8-EF 子表（此前发现的"排序词典"）
- ⚠️ 此前我读的 0x1CCCA3 = 多加了 0x200 的错误位置（J2E 偏移为无头格式）

**其他关键情报**：
- `82/A593` = 令牌解析例程（Rev0；Rev1 在附近）——反汇编入口
- `A114` = 指针装载：`from $0D6C, get pointer from 24bit table at 01/9872`
- `$C5:F20C` = 对话文本块中部（= 文件 0x22F20C，与 J2E 的 22F40C 吻合）
- `Transfers font FROM #$C000 to C200,x` = 字库上传源
- `F9DB F5BA = Shiori's kanji`（詩織）—— 名字表页 delta = +6E0B，与假名页相同
- 清川 = F7BA/F7F2（对话页 delta = +6706）→ **每页delta不同实锤**（詩織+6E0B vs 清川+6706）

**多页增量表现状**：82:+6E0B 83:+6DBD 8A:+689E 8B:+685A 8C:+6816 8D:+67D3
8E:+678E 8F:+674B 90:+6706 91:+66C3 92:+667E 93:+663A 95:+65B3 96:+656E
97:+652A 98:+64E7（8A-98 段内 -0x44/行；83-8A 段 -0xB9/行；82 固定 6E0B）

### 池指针公式验证结果（否定记录，避免重复尝试）
按 J2E 公式（text table @0x2371BF + 字偏移×2/×1）解码 c001a0 指针目标：
0x237FD9 / 0x238BCD / 0x237C03 / 0x23A023 等全部无日文可读文本。
结论：指针语义 ≠ 简单的"文本表基址+字偏移"，或表基址不同，
或池文本有独立编码层 → 需引擎反汇编（82/A593 解析例程，Rev0 地址需
按 Rev1 校准）或模拟器断点动态跟踪。黑盒猜测到此为止。

### ★ 令牌分派机制破译（0x12540 处 65816 代码手工反汇编）
```
012540: ad 0a 0d    LDA $0D0A      ; WRAM $0D0A = 16位当前令牌寄存器
012543: 29 f0 00    AND #$00F0     ; 取低字节高半位 = 列号
012546: c9 a0 00    CMP #$00A0     ; 列 A0 → BEQ 处理器
01254B: c9 b0 00    CMP #$00B0     ; 列 B0
012550: c9 c0 00    CMP #$00C0     ; 列 C0
012555: c9 d0 00    CMP #$00D0     ; 列 D0
01255A: c9 e0 00    CMP #$00E0     ; ≥E0 → BCS
```
- **列 A0 处理器** (0x12560): `AND #$000F`（低 4 位 = 页索引）→ XBA → JSR $A114
  （= J2E 日志的指针装载器，24 位指针表 @ $01:9872）→ 组合出词组串地址
- 证实：字符集按 16 码一列组织，每列独立处理器；令牌 = 16 位值
- $0D0A 可在 stable-retro 的 WRAM 中直接读取（偏移 0x0D0A）
- 解析例程区间 = 文件 0x12500-0x12700（bank $02，J2E 日志 82/A593 ✓ 文件换算 0x12593）

## 字库（已解包，out/font/）

- 主字库：文件 0x3E8000-0x400000 = 3072 个 16×16 1BPP 字形（32B/字，MSB 在左），
  `0x3E8002` 起第一个字形为空格。顺序 = 码表顺序（符号→假名→汉字）。
- 0x3Cxxxx-0x3E8000 疑似第二套 UI 字库（待细分）。
- 渲染管线实测（WRAM 0x10300）：字形以 2bpp（plane0=填充，plane1=阴影+1,+1）上传 VRAM，
  阴影由引擎叠加 → 汉化只需替换 1BPP 本体。
- 容量 3072 ≈ GB2312 常用字规模，整库替换可行。

## 名字输入画面汉化 (2026-09-16 完成)

# ★★★「码→字形」映射 100% 破解 (四字渲染全部命中) ★★★
## 完整公式
码 = [页引导 F0-FF][低字节 L]
字形序号 = 0x0D5A + $80:D4E4表序号 (若 L ∈ [AB,FC], 即假名修正)
         = L (否则, 直接)
字形地址 = SNES (0xFD+页号):0x8000 + (序号 mod 0x492)×28
  其中 页号 = 序号 ÷ 0x492 (页容量 = 0x492 字形!)
file = (bank-0x80)*0x8000 + 0x8000 + (序号 mod 0x492)*28 - 0x8000

## 架构定案
字形库 = bank $FD-$FF (file 0x3E8000-0x3FFFFF, 98304B)
  分页: 每页 0x492 字形 (页容量 1170×28 = 32760B)
  bank = $FD + 页号 (页3 = bank $00 → 头部区!)
字形 = 28B = 14x16 1bpp (行优先 2B/行, MSB左)
码低字节 = 池内字形序号 (直接索引)
假名 AB-FC → 修正表($80:D4E4)映射到序号 0x0D5A+
