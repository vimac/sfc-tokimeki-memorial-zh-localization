## 三、池行的终止符账（#36 那一族的实测）

477 条逐行量，两镜像各按自己的 raw 段走一遍（日文侧 `jp_raw_runs`、中文侧 `line_raw_runs`）：

| 量什么 | 结果 |
| --- | --- |
| 段内「站在头上的控制字节」总数 | 日文 336 → 中文 1,011 |
| 差在哪里 | **361 条差在填充尾巴**（`$0B?`＋`$0A` 0~1 枚）；段内其余形状一模一样，22 种序列里非填充部分只有 `$0B` 与 `$12/$13` 姓名插入码 |
| `addr+span` 那个字节动过没有 | **477/477 没动**（422 条是 `$0A`、39 条 `$2E`、16 条 `$A0`）——填充永远不越过 span |
| 日文有没有把终止符写在 span **里面** | **0 条**。所以「中文把日文的终止符盖掉了」这种丢终止符（= 两条记录并成一条）的形状，本镜像**一条都没有** |
| 裸 `$0A` 连续长度（span 内＋紧后面那一字节） | 最长 **2**：329 条从日文的 1（只有 span 外那枚）变成 2（填充一枚＋原来那枚），32 条从 0 变 1，**没有任何一条到 3** |

结论：**#36 的形状（一串裸 `$0A`）在当前镜像里不存在**；存在的是修复之后那个最小形状——
每行至多多一枚填充终止符，后面紧跟日文自己那枚。这个形状不是纸面推导：
批次T 修复当次就在验收盘上新鲜走查实证「心形格 A 恢复派发」（`git show 117e658`），
此后每次出货都由 `bank lines: 477/477` 那条回读盯着行数与逐行解码，
而**「填充只有一枚」这件事以前没有闸门**（`verify_ui_lines` 拿镜像去比**同一个函数**算出来的期望字节，
所以填充写法改了它照样绿）——这就是 ① 第 1 条补上的东西。
