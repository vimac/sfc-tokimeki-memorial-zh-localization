# 文本派发器里各控制码的宽度

数据全部由 `tools/ctrl_advance.py` 从母盘实测得出：它顺着 file `0x4B0B` 那张表逐个看了 48 槽，
其中 47 槽（`$00`–`$2E`）是真处理程序，第 48 槽 `$2F` 已经出了表尾、读出来是代码字节 `$00A9`；
每槽都去追函数尾部跳到哪条前进桩。`$80:CA6D` 的派发器是这样分流的：

```
80CA6A: F4 00 00       PEA #$0000        ; 给子解析栈压一个零标记
80CA6D: A7 B4          LDA [$B4]         ; 读游标处的字节
80CA72: C9 F0 00       CMP #$00F0
80CA75: 10 67          BPL $CADE         ; $F0-$FF 双字节字模，索引 = 字 − $F000
80CA77: C9 E8 00       CMP #$00E8
80CA7A: 10 44          BPL $CAC0         ; $E8-$EF 双字节 sub-text 宏（bank $C3）
80CA7C: C9 A0 00       CMP #$00A0
80CA7F: 10 25          BPL $CAA6         ; $A0-$E7 单字节 phrase 宏（bank $B9）
80CA81: C9 40 00       CMP #$0040
80CA84: 30 65          BMI $CAEB         ; $00-$3F 控制码
80CA86: 38 E9 40 00    SEC : SBC #$0040  ; 剩下的 $40-$9F 拿去查 $83:8000 那张 BE16 表
80CA8A: 0A AA          ASL : TAX
80CA8C: BF 00 80 83    LDA $838000,X
```

（复现：`python3 tools/dis2.py rom_original_japanese.sfc 0x4A6A 0x26 0x80A6A`。）

前进桩就是 `$CA9A/$CA9C/$CA9E/$CAA0/$CAA2` 处叠起来的一串 `INC $B4`，所以处理程序尾部跳到哪一
条，就交代了这条码吃掉几个流字节：`JMP $CAA2` = 1、`JMP $CAA0` = 2、`JMP $CA9E` = 3、
`BRA $CAA0` = 4。

## 吃操作数的码

| 码 | 处理程序 | 吃掉字节 | 作用 |
|------|---------|-------------|--------------|
| `$00` | `$CB69` | 2 | 1 个操作数字节 |
| `$01` | `$CB73` | 2 | 1 个操作数字节 |
| `$09` | `$CC20` | 3 | `LDA [$B4],Y`（Y=1）读一个 16 位操作数存进 `$0A26/$0A28`：**设置像素写游标** |
| `$28` | `$CE48` | 2 | 操作数 = 以帧计的延时，`(n+1)*4` |
| `$30`-`$37` | `$CD8C` | 2 | 读 `LDA [$B4]` 的 16 位，低字节是码、高字节是操作数：操作数选 ROM 调色板表项，码选 WRAM 里的落点 |

`$30` 以下剩下的码，序章执行到的那些全都只吃 1 字节：
`$0A $0C $14 $18 $1C $24 $25 $26 $29 $2E`。  `$30-$37 xx` 是「装色」那一族，吃一个操作数、
也得小心，只是序章一条都没执行到；`$38-$3F` 反过来——它不吃操作数，但 block 8 里成对出现了
22 次（见 `control-codes.md` 最后两行）。

**`$09` 不是全宽空格，`$0A` 也不是换行符**，别凭想象用它们：

* `$0A` -> `$CC2B` 是 `PLA / BNE / RTL / STA $B4 / PLA / STA $B6 / JMP $CA6D`。
  顶层解析时栈顶放着 `$CA6A` 压的那个零标记，所以正文里的 `$0A` 弹出零、`RTL` 返回，这次解
  析就结束了；宏体里遇到 `$0A`，弹出的是调用点在 `$CAA6`/`$CAC6` 压下的游标，于是从调用处
  往后接着读。两种情况它自己都只前进 1 字节。
* `$0B` -> `$CC37` 才是换行（`$0A26 += $40`）；`$0C` -> `$CC47` 弹出一层挂起的子解析再重新判断。
* `$2E` -> 表项干脆就是 `$CAA2`，一条 1 字节的空操作。

Block 144 实际执行到的控制码，按种类数一遍（`tools/ctrl_widths.py`）：
`$0A:5  $0C:84  $14:116  $18:1  $1C:1  $24:8  $25:20  $26:1  $29:2  $2E:7`
—— 一共 245 字节，每条都只占 1 字节。所以中文怎么重排都碰不到操作数，游标乱不了。
统计时有个坑：直接在块里按裸字节数 `$00-$3F`，会多数出 60 多个假「控制码」——它们是
`$F0/$F1/...` 字形对的第二个字节（`f0 09`、`f6 00`、`fd 01`），必须按原子走一遍才算数。

## 字库派发细节

`$80:D23D`（两条带共用的字形绘制例程）读 `$0A2C`：bit 4 让索引走 `$80:D4BD` 的假名变体
转接，bit 5 把记录重打一遍，bit 1 选另一种变换。它们都不碰 `$B4`，所以画字形永远不会移动游标。
