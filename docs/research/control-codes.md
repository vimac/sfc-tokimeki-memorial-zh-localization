# 心跳回忆（SFC 日版 Rev 1）——控制码的宽度与语义

本文的结论逐条来自反汇编：从文本派发器（`$80:CA6D`）出发，把它能到达的每个处理程序都拆了一遍，
不是从 `docs/history/` 的旧交接笔记里抄的。

## 派发路径（`$80:CAEB`，file `0x4AEB`）

```
80CAEB: A0 01 00       LDY #$0001        ; Y = 1，下面每次读操作数都用它
80CAEE: C9 38 00       CMP #$0038
80CAF1: 30 03          BMI $CAF6
80CAF3: 4C 67 CD       JMP $CD67         ; $38..$3F -> 处理程序 $CD67（按 码−$38 索引）
80CAF6: C9 30 00       CMP #$0030
80CAF9: 30 03          BMI $CAFE
80CAFB: 4C 8C CD       JMP $CD8C         ; $30..$37 -> 处理程序 $CD8C（落点 = (码−$30)×8+2）
80CAFE: DA             PHX
80CAFF: 0A             ASL
80CB00: AA             TAX               ; $00..$2F -> 查 file 0x4B0B 那张表（$2F 已在表尾之外）
80CB01: BF 0B CB 80    LDA $80CB0B,X     ; 处理程序地址，小端
80CB05: FA             PLX
80CB06: 85 00          STA $00
80CB08: 6C 00 00       JMP ($0000)
```

（复现：`python3 tools/dis2.py rom_original_japanese.sfc 0x4AEB 0x40 0x80AEB`。）

**分发表共 47 项（`$00`-`$2E`），在 file `0x4B0B`。** 查表之前先分流，所以 `$30` 以上的码根本
进不了这张表；表尾那一格（`$2F`）已经是后面代码的字节 `$00A9`，**没有处理程序**——一条流里要是
真执行到裸 `$2F`，跳的就是 `$00A9`。142 块的 `ctrl` 列里 `$2F` 一次都没有；它在盘上只出现过
一次，是 block 89 里 `$03` 的一个操作数。`$38`-`$3F` 确实活着，而且是**成对**用的（block 8 各
22 次，全库 `$39` 与 `$3B` 各 61 次），所以别把它们当成没人碰的摆设。

宽度直接从处理程序的尾部读出：游标前进链是 `$CA9A/$CA9C/$CA9E/$CAA0/$CAA2` 处叠起来的
五条 `INC $B4`，所以 `JMP $CAA2` 吃 1 字节、`$CAA0` 吃 2、`$CA9E` 吃 3、`$CA9C` 吃 4、
`$CA9A` 吃 5。

## 宽度表（吃掉的字节数，含码字节本身）

| 码 | 处理程序 | 宽度 | 读操作数 | 作用 |
|---|---|---|---|---|
| `$00 xx` | `$CB69` | 2 | 0 | `LDA #$0000 : JSL $D23D`，画空白格；操作数被忽略 |
| `$01 xx` | `$CB73` | 2 | 2 | **计算式前跳**（见下） |
| `$02 xx` | `$CB8B` | 2 | 0 | 调用：先把「游标 +3」压栈，再按操作数 `STA $B4`——跳到同 bank 内的 1 字节地址 |
| `$03 xx yy` | `$CB9C` | 4 | 2 | 用 2 个操作数选中一个 16 位 WRAM 字，`JSL $CFC5`，前进 4 |
| `$04 xx` | `$CBD0` | 2 | 1 | `STA $0A2C`，**设置字形风格标志**（bit0 图层、bit1 描边、bit4 假名、bit5 加粗） |
| `$05` | `$CBDB` | 1 | 0 | 把 `$7E:9FFE` <-> `$7EA000` 的 16 像素格在 `$0A26` 附近对拷，`INC $0A26` |
| `$06` | `$CBF9` | 1 | 0 | `LDA $0A26 : STA $0A28`，记下行首格 |
| `$07 xx` | `$CC02` | 2 | 1 | `$0A26 += operand`，格游标右移 |
| `$08 xx` | `$CC11` | 2 | 1 | `$0A26 = $0A28 + operand`，定位到当前行的绝对格 |
| `$09 xx yy` | `$CC20` | 3 | 1 (16-bit) | `$0A26 = $0A28 = word`，**绝对像素游标**，前进 3（不是空格） |
| `$0A` | `$CC2B` | 1 | 0 | 宏返回：`PLA : BNE : RTL / STA $B4 : PLA : STA $B6` |
| `$0B` | `$CC37` | 1 | 0 | 换行：`$0A26 = $0A28 + $40` |
| `$0C` | `$CC47` | 1 | 0 | 弹出一层挂起的子解析（类似 `PLA : PLA : $0A`） |
| `$0D` | `$CC4E` | 1 | 0 | 基于 `$0A22` 的格计数器运算 |
| `$0E` | `$CCB5` | 1 | 0 | 大处理程序（178 字节），两次 `JSR` 之后前进 1 |

| `$10` | `$CDC9` | 1 | 0 | `LDA #$0010 : STA $0A2C`，切到假名变体（「手写体」）字库 |
| `$11` | `$CDD2` | 1 | 0 | `STZ $0A2C`，切回普通字库 |
| `$12` / `$13` / `$16` | `$CDD8`/`$CDE8`/`$CDF8` | 1 | 0 | 压入游标，再按 WRAM 的玩家姓名缓冲 `$0E00`/`$0E08`/`$0E10` 重新派发 |
| `$14` | `$CE7D` | 1 | 0 | 框/行几何：`JSR $CF36`，随后一个循环压入 `$0C` 并 `JSL $81E86C` |
| `$15` | `$CE9A` | 1 | 0 | `JSL $80D0B8 : LDA #$0008 : JSL $80C563` |
| `$17` | `$CE08` | 1 | 0 | 压入游标，切到 `$83:8318` 那张**按索引分支的记录表**再派发：表首是 `$01 $3A`（运行时选择器 `$003A`，机制见下节），每条记录以 `$0A` 返回。另外把 `$00C4×3 + $80:CE3A[X]` 记进 `$0A3A`（这个字在 `$80-$83` 的代码里找不到读点）。语料 142 块里执行 376 次；英文同人的工具把它整个当「玩家名占位」用，与「按索引打印一条姓名/称呼记录」一致。表头 `0x18318`–`0x1835B` 本盘与母盘逐字节相同（`0x1835C` 往上才是我们重写的九个能力标签） |

## `$01`：按顺序往下读就是在这里错开的

```
80CB73: B7 B4          LDA [$B4],Y   ; 操作数 = 紧跟在码后面的那个字节
80CB75: A8             TAY
80CB76: B9 00 00       LDA $0000,Y   ; 拿去查 WRAM 的一个 16 位字（运行时的选择器）
80CB79: 18             CLC
80CB7A: 69 03 00       ADC #$0003
80CB7D: A8             TAY
80CB7E: B7 B4          LDA [$B4],Y   ; 再读回流里那张跳距表的一项
80CB80: 29 FF 00       AND #$00FF
80CB83: 18             CLC
80CB84: 65 B4          ADC $B4       ; $B4 这会儿还是 `$01` 自己那个字节
80CB86: 85 B4          STA $B4
80CB88: 4C 6D CA       JMP $CA6D
```

（复现：`python3 tools/dis2.py rom_original_japanese.sfc 0x4B73 0x18 0x80B73`。）

`新游标 = c + 位于 c + word@($0000+操作数) + 3 的那个字节`——跳距以 `$01` 自己那个字节为基准。
操作数决定用流里的哪张距离表，运行时字决定取这张表的第几项。block 8 里 `$01` 的操作数是 `$A0`
共 160 次、`$00` 共 50 次，所以那两个 WRAM 选择器住在 `$7E:00A0` 与 `$7E:0000`。这样读下去当然
还有内容，但 `$01` 后面的字节有一部分是跳距表，不是正文。

## 读英文同人那份资料的正确方式

`reference/` 里的 J2E 资料提到过的一些「特殊字节」值不了多少：他们的 dumper 把任何没映射的字节
连同它的操作数一起打成 `<$XX>`（`reference/j2e_full/tokistuff_x/tokid.bas:1734,1812`），所以对
`$00-$3F` 他们**只有猜测**。反过来，他们的**地址表**几乎全对，只是按「带头 +`$200`」写的：
`009A72`＝我们的 `NAME_PTRS 0x9872`、`009C25`＝`TEXT_PTRS 0x9A25`、`018200`＝码表 `0x18000`、
`2198A8`＝`0x2196A8`。拿他们的地址来核对，先减 `0x200` 再对表。

## `$C0` 后面跟 `$01 $A0`：一条变量插入记录

英文同人的插入工具拿一个字节串当「这里要插变量」的签名：`C0 01 A0 …`
（`reference/j2e_archive/tokistuff/TOKIT.BAS:2109`）。这个形状在本盘上读得通，而且不神秘：
`$C0` 是 `$A0-$E7` 段的宏调用，紧跟的 `$01 $A0` 就是上一节那个变量分支（运行时选择器住在
`$7E:00A0`，block 8 里 `$01` 有 160 次的操作数正是 `$A0`）。所以它是「宏体 + 按变量选分支」
这个常用组合，不是什么特殊标记。

他们另外记了一张「`C0` 该看几个字节」的表在 `0x9FB0`（`reference/j2e_archive/tokistuff/toki.txt:1`）。
全盘搜不到以 `$1FB0`（= file `0x9FB0`）为操作数的读指令；唯一读 `$9DB0,x` 的代码在 bank `$84`
自己那半区（file `0x14B9C`、`0x14BEE`，取来还要 `AND #$000F`），跟 `$C0` 无关。所以那条笔记
按「他们工具自己的配置」处理，**别当引擎结构引用**。

记录密集的地方在 file `0x232D79` 一带，本盘与母盘在那里零差异；有没有丢插入记录不用数字节
（`C0 01 A0` 三元组在母盘的文本区里有两万六千个，绝大多数是字模码低位撞出来的巧合），
`docs/research/blockN_work.tsv` 的 `ctrl` 与 `runs` 两列已经逐原子解过一遍，加上构建的
round-trip 断言就是证据。

## 对打补丁的影响

1. 凡执行 `$00/$01/$02/$03/$04/$07/$08/$09/$0F/$28/$30..$37` 的块，都必须按这些宽度来走。
   把它们当 1 字节读，后面每个原子都会失步：症状是词都对、却凭空混进假音节
   （`（最近、女子生徒じゃないか？）` -> `（最よ近、女演奏生じゃないか徒？」`）。
2. 由于 `$01` 跳到 `c + <distance byte>`，翻译用到它的块只有两条路：**保住每个原子的偏移**
   （block 144 那种定长 span），或者把距离字节一起重算。保长度是安全的默认选择。
3. `tools/block_boxes.py` 已按这些宽度实现，把一个块切成以 TERM 分隔的段（逐块 dump 是派生
   数据，按需重生成——见 AGENTS §二）。
