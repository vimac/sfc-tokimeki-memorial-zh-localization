# 姓名输入键盘：三张表的实测与「换成常用名汉字表」的成本

量于 2026-09-25，母盘 `cd36eb8982de4bf8369deb9f2f23e590` + 当前交付盘。
数据都在 bank-`$83` 的 `0x1F2D4-0x1F890`（`build_prologue.KEYBOARD_TEXT_REGION`），
按 token 走：`≥$F0` 吃 2 字节是一个字格，`$00` 是行分隔，`$01 xx xx` 的操作数本身就是一个字格索引，
`$0A` 收尾。解析脚本是一次性的（`/tmp`，用完即删），下面是它量出来的东西。

## 一、四页键盘分别是什么

页标签在 `0x1F157 かな`／`0x1F15D カナ`／`0x1F163 記号`／`0x1F172 漢字`，
外加 `0x1F14A 前頁`／`0x1F150 次頁`。页数是引擎写死的，加不了新的一页。

| 页 | 池行 | 键数 | 键帽现在画什么 | 按下去输入什么 |
|---|---|---|---|---|
| 平假 | `0x1F4C2` 起第一条 `$00` 分隔行 | 100 格 | 假名的**同音中文**（啊衣呜哎哦 / 妈米木么摸 / 卡基苦刻科…） | 那一格自己的索引＝假名 |
| 片假 | 紧接其后 | 87 格 | 同上 | 同上 |
| 符号 | | 数字/字母/标点若干 | 中日同形，看不出是日文 | 同上 |
| 汉字 | `0x1F6A0` 起，59 行 | **117 格** | **日文形体的汉字**（亜 塩 厳 覧 値 読 鈍 認 聞 麺 類 錬 瑠 鑓 糎 匁…） | 那一格自己的索引＝该汉字 |

汉字页每行的形状是「`空格 + 假名读音标签 + 汉字`，第二个汉字挂在 `$01 <字格索引>` 上」，
例如 `あア亜` + `$01 F1ED`(杏)。读音标签是假名索引，按 §五 的规矩不能动；
**汉字键的键帽和它输入的值是同一个索引**，所以换字＝换索引，一步到位。

## 二、这块表现在的两个问题

1. **汉字页是全盘最大一块「看得见的日文」。** 117 个键的记录都被字库整带回填重画过，
   但重画用的是**同一个日文码位**的文泉驿点阵（回填只把假名换成同音中文，汉字保持原码位），
   所以屏幕上仍是 `塩 厳 覧 値 読 麺 類` 这类日本新字体。
   静态链看不见它：`render_prologue.py` 只走 TEXT_PTRS 的块，这块住在 bank 池里，
   构建报告只有 `bank lines: 477/477` 这种 round-trip 断言覆盖它。
2. **假名页是发音表，不是名字表。** 键帽画的是同音中文、按下去打假名，玩家既读不通也组不出名字，
   这就是用户点名的「不实用」。

## 三、成本：换汉字页的 117 个键（便宜，且能顺手把问题 1 清掉）

* **字节**：每格 2 字节，换索引不改行长、不改 span、不动偏移表——池行的骨架原样保住。
* **字库**：键帽和输入值是同一个索引，所以只要目标字**已经有一个格**就能直接用。
  现成的 2,303 个格覆盖得住：拿一份 203 字的候选名表实测，180 字已有格，23 字要新格
  （辅 翔 拓 昭 仁 俊 菊 云 惠 咲 纱 兰 桃 莲 瑞 禄 寿 绢 锦 绣 芳 煌 洁）。
  新格要从低频字那里领槽（`tools/charledger.py tail 60`），领一次就得重跑全静态链——
  码表是零和的，这是唯一真正花时间的地方。
* **要写的代码**：`build_prologue.py` 里加一张 `KEYBOARD_KANJI`（117 项：读音标签 + 两个汉字），
  写入时断言 ①行长不变 ②每个键索引的记录位图 == 该字的文泉驿点阵。约 40 行。
* **验证**：这一页只在姓名输入画面出现，`render_prologue` 走不到，所以每次改动都要开模拟器走进去看
  （冷启动→相册→姓名输入，约 5 分钟一条 trace）。
* **未知风险只有一个**：AGENTS §五 记着「把键盘池那 71 行重编成中文索引会让姓名输入初始化跳飞、纯黑屏」
  （批次U #42 实测过那颗盘）。炸的原因是那次把整块区域按 `UI_TEXT_ROWS` 的规矩重写成「纯字格 + 空白格填充」，
  于是把行分隔 `$00` 和汉字键挂的 `$01 <字格>` 操作数一起抹平了——引擎走的骨架没了。
  本方案不一样：**只改字格里那 2 个字节，控制流一个字节都不动**，所以理论上不会重演那次事故。
  但这仍然是推断不是实测，动手前先用**一个键**做实验（换 1 格 → 重建 → 走进去看），
  20 分钟就能把这个未知消掉。

结论：**一到两批活**。表文案（117 字怎么排、按读音还是按姓/名分页）是大头，工程是小头。

## 四、成本：动假名页（贵，别做）

假名键的索引就是它输入的值，而那 71 个假名索引同时是整个码表的 `SB` 带入口
（`0x18000` 的 96 项里有 71 项是假名）。把假名页换成汉字等于重做全局码表，
所有已发布的框都要重排——而且玩家就没有输入假名（昵称、片假名）的地方了。
想要「实用」，正解是汉字页那一页，不是把假名页拆了。
